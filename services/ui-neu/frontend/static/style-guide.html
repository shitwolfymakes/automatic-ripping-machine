ui-neu Design System

Tokens are the only raw values, blocks are the shared looks, components scope what is genuinely local, and markup carries layout only. Everything on this page is rendered with the system it documents — switch your theme and it follows.

01 · Architecture

Four layers, one direction

Every visual decision has exactly one home. Work down the list and stop at the first layer that fits:

Tokens — src/lib/styles/tokens.cssEvery colour, radius, shadow and motion value. Nothing else may hold a literal.
Blocks — src/lib/styles/components/*.cssA look shared by two or more components: button, panel, badge, table. One file per block; the header comment is its contract.
Layout helpers — layout.css, utilities.cssArrangement (stack, cluster, grid-2) and a few behaviours (tabular, spin).
Component-scoped <style>What only that component needs: its grid template, a metric delta on a block, a one-off look.

The cascade facts worth memorising:

  • Tailwind’s utilities layer beats our components layer, and Svelte scoped styles compile unlayered, beating both regardless of specificity. A scoped rule therefore overrides a block with no !important — which is banned outright.
  • Per-instance overrides use a custom property: set style:--jt-accent in the template, read var(--jt-accent) in a scoped rule. The JobCard precedent.
  • A colour scheme’s token map is written as inline style on <html> and beats every stylesheet, including the scheme’s own.
  • table/table-row/table-cell are also Tailwind display utilities; the responsive-prefixed forms are banned, and rules that must outrank a utility live in @layer utilities.
02 · Tokens

The closed set

Primitives are private to tokens.css; components and themes reference semantic roles only. Every role flips in .dark — never write a dark override in a component. The set is closed: a missing exact match is a named collapse onto the nearest role, recorded in the PR, never a new token.

05 · Interaction, elevation, icons & structure

The conventions between the blocks

Interaction states
  • Focus: one global ring — :focus-visible { outline: 2px solid var(--color-primary); outline-offset: 2px }. Never removed, never a second style.
  • Hover climbs the tint ladder: transparent → tint-1 (rows, ghost) → tint-2 (selected); filled controls darken to --color-primary-hover.
  • Disabled is opacity: .4 + not-allowed, from the block — never restated darker.
  • Busy is [data-busy="true"], not a spinner class.
  • Reduced motion: base.css zeroes the motion tokens and caps every animation; ride the tokens and it is handled for you.
Elevation & stacking — frozen
tiershadowzwho
resting--shadow-1autocard, panel, stat
floating--shadow-240flyout
overlay--shadow-250modal, slide-over

No other z-index exists; a stacking problem is solved by DOM order or a portal, not a bigger number.

Iconography

lucide-svelte, coloured by currentColor. Size is owned by the containing block: nav 20px, glyph 16px, btn-icon 14px, the chevron 14px (rotating on [aria-expanded]). Targeting a lucide instance needs :global( — allowed only with a comment.

Responsive structure — three breakpoints
widthwhat changes
640pxgrid-2/grid-3 collapse to one column
1024pxsidebar replaces the drawer; responsive-table stacks rows into label/value cards — give every cell data-label="Column"
1536pxthe sidebar stats panel appears

Wide content scrolls in its own overflow-x-auto container; the page body never scrolls sideways.

Page states & microcopy
  • Loading: skeleton shapes in the layout the data will fill, never a lone spinner.
  • Empty: a muted sentence saying what will appear and how to cause it.
  • Errors: alert alert-danger (page-level: alert-lg) saying what failed and what to do; field errors are field-error + [aria-invalid].
  • Copy: sentence case (themes uppercase for themselves); controls say what they do; three dots, not the ellipsis character; no em-dashes, no unicode-as-UI, no emojis.
06 · Layout helpers

Arrangement classes

stack (column, 1rem gap; -sm/-lg), cluster (wrapping row), grid-2/3, page, page-header, page-title, split. The one sanctioned exception to role naming: they say what they arrange.

Two flexbox facts that each bit hard during the migration: a stack is a column flexbox, so children stretch full width regardless of display — shrink one with align-self: flex-start; and flex gaps do not collapse like block margins, so a child’s margin-bottom adds to the gap instead of merging into it.

07 · Dynamic values

Custom properties, not style strings

<div class="progress-fill" style:--progress="{pct}%">          <!-- the block reads var(--progress) -->
<div class="card card-status" style:--jt-accent={accentVar}>   <!-- scoped rule reads it: no !important -->

style="..." string attributes are banned; style: directives carry custom properties only (plus the Flyout position allowlist). Theme hooks are data-* attributes — data-progress-track/-fill, data-sidebar-stats, data-poster, data-indeterminate — kept on elements even where the block class is present, because schemes key off them.

09 · Scoped styles

The rules for local CSS

  • Never copy a block’s declarations — use the class, add deltas.
  • Original metrics win over block defaults. A compact control keeps field-control and restates its own padding/height in scope, with a comment saying why.
  • Line heights are unitless calc ratios: calc(1.25 / 0.875) for text-sm, calc(1 / 0.75) for text-xs. Fixed lengths pin the line box when a theme resizes type; rounded decimals (1.4286 → 19.9996px) shift dense pages by sub-pixel accumulation.
  • No literal colours, no !important, no dark: — tokens flip on their own, and scoped styles already out-cascade the blocks.
10 · Building a new component

The decision tree

For every visual element in a new component, work down and stop at the first fit:

A block already looks like thisuse the block class, done.
A block almost looks like thisblock class + a scoped delta restating only what differs, with a comment naming the reason.
Blocks compose into thiscombine them with layout helpers: panel + stack + field covers most forms.
Only this component wants ita scoped style, prefixed with the component’s name.
A second component will want ita new block — see Growing the vocabulary.
Component file anatomy
<script lang="ts">
  // imports, a typed Props interface, then $props()/$state()/$derived
</script>

<!-- markup: block classes + allowed layout utilities; state as aria-*/data-*;
     dynamic values as style:--x -->
<div class="card" data-status={job.status} style:--jt-accent={accentVar}>
  <div class="card-header">
    <h3 class="card-title">{job.title}</h3>
    <span class="badge badge-status" data-status={job.status}>{label}</span>
  </div>
</div>

<style>
  /* scoped styles LAST; every class prefixed job-card-*; overrides carry a
     comment naming the original value and why */
  .job-card-meta { font-size: .75rem; line-height: calc(1 / .75); color: var(--color-text-muted); }
</style>
  • One component per file under src/lib/components/ (route-private pieces live beside their +page.svelte); tests are colocated.
  • Interactive state is reflected in the attribute that styles it — the code sets aria-pressed/data-selected, the CSS keys off it. Never a parallel active class.
  • Themeable surfaces get the published data-* hook even where a block class is present.
  • Definition of done: vitest + check green, lint:styles --files at 0, and parity held (or a named collapse recorded) on every existing screen touched.
11 · Growing the vocabulary

Promotion, not duplication

Element or modifier on an existing block
  • Add the rule inside the block file’s @layer components, tokens only.
  • Extend the file’s header comment — it is the contract.
  • Add the class to the BLOCKS registry in blocks.test.ts.
  • Update the vocabulary tables here and in ui-neu-theming.md.
A new block (second consumer appeared)
  • Create components/<block>.css: header comment (Elements / Modifiers / State), @layer components, tokens only, calc line-height ratios.
  • @import it from app.css (the index).
  • Register every class in blocks.test.ts — header, class list and no-raw-colours are enforced from then on.
  • Convert the original consumers, delete their scoped duplicates.
  • Document it in both guides; themes may target it from that moment, so name its state hooks deliberately.
  • Parity must hold on every screen the converted consumers appear on.

Adding a token: almost never. The set is closed — a colour with no exact role collapses onto the nearest one, recorded. A genuinely new role needs a second consumer, light + dark values, a family-consistent name, the .dark twin, a tokens.test.ts entry, and a spec amendment. A new theme hook is a published data-* attribute (the data-poster pattern), listed in ui-neu-theming.md and stable from its first release.
